# 浏览器 Agent 迭代蓝图（学习向 · 产品级规划）

> **文档性质**：这是一份"通用浏览器 Agent"的分阶段迭代规划，同时是一份**Agent 开发教学说明**——
> 它不仅列出每一步要迭代什么，还解释**为什么要在这个时间点做这件事**。
>
> **它不是什么**：它不是技术方案，也不是接口设计。每个阶段只讲"能力 + 动机 + 边界"。
> 具体牵扯到的技术选型与实现方案，**由 AI 在使用本文档时与你对齐、向你澄清后再确定**，
> 本文档不提前把实现写死。
>
> **怎么用**：每期开工时，只把「对应阶段章节」交给 AI，并声明"本期只做该阶段范围内的事，
> 范围外一律记入后续阶段，不提前实现"。凡遇本文档没写清的技术决策，AI 必须先向你提问、
> 达成共识再动手，不得擅自折中。

## 一、大框架：浏览器 Agent 到底是什么

一句话：**一个能在真实网页上「感知 → 推理 → 行动 → 观察结果」并循环推进、直到完成任务的程序。**

任何浏览器 Agent 的能力，都可以挂到这四个动作 + 一条贯穿的生命周期上：

| 动作 | 含义 | 本项目现状 |
|---|---|---|
| 感知 Perceive | 读取页面/标签页/网络等外部真实数据 | 已有第一个只读工具（读当前页） |
| 推理 Reason | 让模型基于真实数据决定下一步 | 已有流式对话 |
| 行动 Act | 对页面产生副作用（点击/填写/导航） | 尚未开始 |
| 观察 Observe | 把行动结果回灌给模型形成下一轮决策 | 已成环（有界 model–tool 循环，阶段 3） |

**贯穿生命周期**：取消、断线重连、后台被杀后恢复、成本与轮次的预算控制。

### Agent 开发七条心法（每个阶段都要回到这里自检）

1. **模型决策，代码执行。** 模型只负责"选哪个工具、传什么参数"；真正的流程控制、硬上限、
   截断、重试全部写在确定性代码里。绝不让模型自由拼装能操作页面的代码。
2. **一切副作用必须有界。** 轮次、条数、频率、字节数都要有硬上限，超限即停并可解释。
3. **可取消是底线，不是加分项。** 任何一个阶段（生成中、执行中、等待确认）都要能被干净中断，
   不留幽灵状态。
4. **状态必须扛得住"后台随时会被杀"。** 浏览器扩展的后台进程随时会休眠/重启，未完成的流程
   要么能恢复、要么能干净终止。
5. **来自页面的内容永远是不可信输入。** 网页正文里出现的"指令"只能被转述/分析，绝不能提权、
   覆盖系统规则、或伪装成用户/记忆/档案。
6. **最小权限。** 默认只拿完成任务所必需的最少权限；需要更大作用域时，走"运行时按站点征求同意"，
   而不是一开始就全量索取。
7. **先能调试，再敢自主。** 系统的自主性越强，越要先有结构化观测（每一轮发生了什么）兜底，
   否则复杂度上来后就再也定位不了问题。

### 分层方向（所有阶段共同遵守）

```
entrypoints（浏览器各上下文入口） → components / hooks（界面与交互） → lib（领域与能力内核）
```

上层可依赖下层，下层绝不反向依赖上层；同一层内部按"概念/能力"组织目录，不散落文件。

## 二、为什么是这个迭代顺序（读这一段就够理解全局）

新手最常见的错误是"先把工具堆得多、再把循环一把上"。正确的依赖关系是：

```
基座与护栏 → 单个感知工具（打磨透）→ artifact 底座 → 有界循环 + 上下文管理 + 观测
           → 澄清 & 工具族扩展 → 行动（带人审门禁）→ 记忆 & 能力包 → 安全/分发/可信发布
```

关键因果，务必理解：

- **为什么"单个工具打磨透"先于"多个工具"**：一个工具走通"声明→校验→确定性执行→双形态结果→
  错误码→单测"这条完整链路，你就掌握了所有后续工具的**模板**。先深后宽。
- **为什么"artifact 底座"要排在"循环"前面**：一旦多步连续执行，大结果（整页正文、抓取数据）
  会把上下文窗口迅速撑爆。**必须先有"大结果落地、只把引用+预览喂回模型"的通道**，循环才有意义，
  否则循环跑两轮就崩。这是很多人踩过的坑。
- **为什么"观测"要和"循环"同期，而不是等出 bug 再补**：循环的失败是"跨多轮"的，没有每轮结构化
  轨迹，你根本无从判断"第 3 轮为什么没调工具/为什么超预算"。可观测性是自主性的前置投资。
- **为什么"行动"排在很后**：读是只读、无副作用、错了顶多答不准；**写（点击/提交）是不可逆副作用**，
  风险最高，必须等人审门禁、权限模型、观测都就位后才引入。
- **为什么"记忆"更靠后**：记忆会引入"把历史/档案注入每一轮"的新提示注入面。要在结构性防注入
  到位之后再做，否则等于给自己开后门。

## 三、分阶段迭代说明

> 阶段号与 SemVer 的映射建议：阶段 0–2 ≈ v0.x 骨架；阶段 3–5 ≈ v1.0 前的"真 agent"成型；
> 阶段 6–8 ≈ v1.x。可按需调整，本文档不锁死版本号。

### 阶段 0 · 基座与护栏 —— 已完成，作为现状基线

**要解决的问题**：一个 Agent 首先得能"稳定地跟模型对话、能被停止、能配置模型与密钥、改一行不会崩发布"。

已具备的能力（不再重造）：流式对话（含取消 / 断线重连回放 / 错误恢复）、可扩展的工具注册表骨架、
密钥本地加密存储、模型配置闭环、通信协议的边界校验、质量门禁（格式化/静态检查/类型/测试/覆盖率/审计/构建）。

**教学点**：护栏（CI、可发布、分层规则）必须在最早建立，让项目**从第一天起就是"可交付"的**。
后续每个阶段都是在"可发布"的地基上加一块砖，而不是攒到最后一次性集成。

---

### 阶段 1 · 第一个感知工具，打磨到"能当模板" —— 基本完成

**要解决的问题**：让 Agent 第一次"看见"真实网页，而不是凭空编。

迭代的能力：
- 一个只读工具：读取当前活动标签页 → 抽取标题/正文 → 归一化 → **按硬上限截断** → 返回。
- 工具契约：`描述 + 单一输入 Schema`（同时用于"绑定给模型"与"运行时校验"）；结果**双通道**
  （给模型的精简文本 + 给程序的结构化数据）；**稳定错误码**（让模型能如实转述失败，而不是编造）。
- 编排采用"一来一回"：带工具生成 → 门禁 → 确定性执行 → 带结果再总结（机制上先杜绝连环调用）。

**为什么先做这一个**：它是"感知"的最小完整闭环，把工具层的所有通用结构（契约、错误、截断、
门禁点位、单测范式）都趟一遍。以后加任何工具都是复制这套模板填内容。

**关键决策点（需 AI 与你澄清）**：注入页面执行代码的边界与自包含约束；截断阈值取多少；
哪些页面类型本就不该被读取（浏览器内部页/商店页）。

**明确不做**：多步循环、写操作、任意 URL 抓取、站点专用工具。

---

### 阶段 2 · Artifact 底座：让大结果有地方去 —— 已完成

> **落地决策记录**（实现时与用户对齐后确定）：工件存 IndexedDB 新增 artifacts 表（复用既有 dexie，零新依赖）；
> 全量统一落地（所有成功结果经单一关口入库，历史只留引用卡：编号+摘要+预览）；预览上限 1500 字、
> 总量上限 50 条超限淘最旧；唯一例外 read_artifact 取回工具标记直通（避免「取回→又变引用」死循环）；
> 关口收口于 registry.executeTool，编排层零感知；旧的 8000 字符截断已删除。

**要解决的问题**：工具产出往往很大（整页正文、结构化数据、文件）。若把它们原样塞回对话历史，
上下文很快撑爆、成本失控、还会把无谓的原文反复喂给模型。

迭代的能力：
- 一个本地暂存/工件层：工具的大输出**落地保存**，回给模型的只是"引用 + 摘要 + 少量预览"。
- 工具结果与"发给模型的消息"解耦：**全量结果不进对话历史**，历史只保留展示用摘要（重放安全）。
- 生命周期与配额：工件的创建/读取/失效、容量上限与清理策略。

**为什么排在循环之前**：见"迭代顺序"一节——这是多步连续执行的物理前提。没有它，阶段 3 直接不可行。

**关键决策点（需 AI 与你澄清）**：工件存哪（扩展本地存储 / 文件系统抽象）、用什么标识引用、
失效与淘汰策略、预览长度取多少。**注意：不要引入未经你同意的新依赖。**

**明确不做**：云端同步、跨设备工件、面向用户的文件管理器 UI（可后续单独评审）。

---

### 阶段 3 · 有界工具循环 + 上下文管理 + 最薄观测 —— 已完成

> **落地决策记录**（实现时与用户对齐后确定）：循环采用**手写有界 while**（LangGraph 方案否决：新依赖 + MV3 SW 适配错位 + 调试黑盒），核心收口于 `lib/agent/loop.ts` 的依赖注入运行器 `runBoundedAgentLoop`，后台只做「组装依赖 + 逐事件映射 + 前后挂压缩/异常终态」的胶水。**压缩用方案 A 分层**：源②循环内步进老化（第 5 步起撤最早步骤预览留工件引用，零 LLM 成本）+ 源①高水位 LLM 结构化摘要（`lib/agent/compaction.ts`，低频批量，摘要+截断下标落 Dexie `compact` 表单行复用不重算）；不用供应商托管 compaction API（BYOK 多端点不可依赖），不引入 SummarizationMiddleware（寄生 LangGraph runtime）。**trace 与循环同期**，最薄=记录+复制，集成到循环入口；结束原因五枚举（completed/max_turns/budget_exceeded/cancelled/error）与真实代码分支一一对应，写入只后台、环形 100 淘最旧、预览必须复用 `lib/diagnostics/redaction.ts` 的 `sanitizeForLog`、token 拿不到实测记「未上报」绝不冒充实测。参数硬编码于确定性代码：MAX_TURNS=8、TOKEN_BUDGET=50000/条用户消息、COMPACT_WATERLINE=24000、KEEP_RECENT=4、老化保留最近 2 步、reactive 硬裁保留最近 2 条重试 1 次。`compactEnabled` 贯通 ModelConfig→secureStore→config 协议→SettingsView 开关（默认可关可见）；触顶/超预算后追加一次「不带工具的收尾调用」保证用户拿到可读交代。

**要解决的问题**：把 Agent 从"问一句答一句、最多调一次工具"升级为"能为一个目标连续多步推进"。

迭代的能力：
- **有界 model–tool 循环**：模型可连续多轮决定"再调哪个工具/是否收敛"；带**最大轮次、成本/token 预算、
  随时可停**；无工具调用即视为完成。
- **上下文管理（压缩）**：长会话/多轮工具结果下，自动对旧轮次做摘要压缩，保住"系统规则 + 最近上下文"，
  压缩对用户可见、可关。压缩与循环**同期落地**。
- **门禁点位真正生效**：每次工具执行前经过一个确认闸口（此阶段仍是只读工具，闸口直通，但必须存在并接线，
  为阶段 5 的写操作做准备）。
- **最薄观测（trace 埋点）**：每轮记录结构化轨迹（时间/结束原因/步数/耗时/token/是否含失败步骤 +
  每步序列），支持"复制本轮为可读文本"以便定位问题。**本期只做"记录 + 复制"这一最薄片**，
  重 UI（面板/下载/分级切换）留到后续。

**为什么这三件一起上**：循环引入复杂度和新失败模式，压缩解决它的上下文压力，观测保证它可调试——
三者是同一枚硬币的正反面，拆开做会互相返工。

**关键决策点（需 AI 与你澄清）**：循环用现成编排框架还是手写有界循环；轮次/预算的具体数值；
"结束原因"有哪些且如何与真实代码分支一一对应（**不能记录一个当前根本产生不了的状态**）；
trace 写入的边界（只能后台写、界面只读）、环形上限、脱敏必须复用既有 sanitizer、
token 拿不到实测就记"未上报"绝不用估算冒充实测。

**明确不做**：多 Agent 协作编排、无人值守长跑、自主扩权限。

### 阶段 4 · 澄清能力 + 感知工具族扩展

**要解决的问题**：循环跑起来后，暴露两类短板——(a) 条件不全时 Agent 会瞎猜；(b) 能感知的手段太少。

迭代的能力：
- **把"向用户提问"做成一个工具**：缺关键条件时，一次只问最重要的问题（而不是每条消息都强制走问答流程）。
- **感知工具族**：读取任意 URL、列出/读取其它标签页、结构化抽取（表格/链接/表单）、必要时截图（取决于所选模型的多模态能力）。
- 每个新工具复用阶段 1 的模板：单一 Schema、双通道结果、稳定错误码、单测。

**为什么澄清工具在此刻出现**：有了循环，Agent 才可能"带着不完整的信息继续跑"，于是"主动澄清"才有价值。

**关键决策点（需 AI 与你澄清）**：工具描述如何写才能防"Agent 病态"（如无脑调用、越权猜测）；
哪些感知手段需要额外权限、如何走最小权限申请；截图与多模态的成本取舍。

**明确不做**：站点专用硬编码工具、把每个网站写成一个适配器。

---

### 阶段 5 · 行动：页面写操作 + 人审门禁 + 作用域模型

**要解决的问题**：让 Agent 从"只会看"到"能干活"——但这是风险最高的一步，必须最后谨慎引入。

迭代的能力：
- **有界动作工具**：导航、滚动、点击、填写等，每个都是版本化、参数受限、作用域明确的操作，
  而非让模型自由生成操作页面的代码。
- **人审确认闸口真正落地**：任何有副作用的动作在执行前必须经用户确认；确认与"执行快照"绑定
  （防止确认后又被篡改）。
- **选择器鲁棒性兜底**：页面结构多变，动作工具需要多候选定位 + 失败可解释，不允许静默乱点。

**为什么排在这么后**：读是只读、错了顶多答不准；写是不可逆副作用。必须等循环、观测、门禁、权限模型
都就位后才做。

**关键决策点（需 AI 与你澄清）**：哪些动作纳入白名单、确认交互形态、失败/超时的回滚与提示、
动作是否记入 trace。**永久坚持：模型只能调用有界工具，绝不自由拼装 DOM 操作。**

**明确不做**：自动提交/自动发送任何站内消息（"生成 ≠ 发送"，发送永远由用户手动完成）。

---

### 阶段 6 · 记忆与能力包

**要解决的问题**：Agent 记不住跨会话的用户偏好与历史；能力难以组织与复用。

迭代的能力：
- **跨会话记忆（分阶段）**：先做"存与召回"，再做"整理/合并"，最后才考虑"自动整理的调度"；
  记忆写入需用户确认，随时可查看/编辑/删除（**记忆透明化**）。
- **能力包（把一组工具 + 权限 + 提示组织成一个可复用单元）**：每个能力声明自己的**工具白名单与沙箱权限**，
  不越权；权限词汇收敛到**单一解析器**。

**为什么记忆在这里**：记忆会把历史/档案注入每一轮，新增一个"被页面内容伪造注入"的攻击面，
必须在结构性防注入成熟后才展开。

**关键决策点（需 AI 与你澄清）**：记忆的数据结构与召回策略、注入预算、防伪造的"信封隔离"方案、
能力包与权限模型的落地形态。

**明确不做**：云端记忆同步、无人值守的自动整理先于确认机制。

---

### 阶段 7 · 安全加固与多上下文分发（持续波次）

**要解决的问题**：一个常驻浏览器、持密钥、能读写页面与记忆的扩展，信任来自工程与安全，而非承诺。

迭代的能力（作为反复出现的专项，而非一次性任务）：
- **提示注入的结构性防御**：把"页面/外部内容不可信"从提示词承诺升级为代码级隔离与标签剥离。
- **权限与授权审计**：作用域不可被重定向绕过；确认与执行快照绑定；密钥在任何导出/日志/诊断中永不含明文。
- **多浏览器分发**：发布流程与商店合规作为护栏维护。

**教学点**：安全不是路线图末尾的一站，而是**每一期都要回看的一条横向轴**。

---

### 阶段 8 · 工程质量与可信发布

**要解决的问题**：把"个人能跑"升级为"别人敢用、可长期维护"。

迭代的能力：CI 矩阵、覆盖率门禁从白名单制走向全模块化、隐私中心（本地数据总览/备份/一键删除）、
无障碍（键盘/焦点/读屏/对比度）、发布治理（版本/变更日志/上架/升级迁移与回滚）、
把重大架构决策沉淀为 ADR。

---

## 四、永久边界（不是路线图缺口，是红线）

- 不绕过目标站点的验证码、登录、访问频率限制；
- 不无人值守自动发送/投递/回复（所有站内发送动作必须用户手动执行）；
- 不读取 Cookie、不调用站点未公开接口；
- 不把局部采集样本描述成平台全量数据；
- 未经授权不上传用户数据/对话（本地优先、无遥测）；
- 不展示或伪造模型的隐藏思维链。

---

## 五、新需求准入七问（含"AI 建议的功能"，先过这七问再排期）

1. 解决哪个真实痛点？（说不出场景的不做）
2. 是否基于真实数据与真实工具结果？（不做演示用的假能力）
3. 副作用是否有界？（轮次/条数/频率/字节都有硬上限）
4. 状态能否持久化恢复？（后台随时会被杀）
5. 失败路径是否明确？（不误报完成、不伪造结果）
6. 是否在永久边界之内？
7. 能否被自动化测试覆盖？

七问全过 → 排入最近的合适阶段；过不了 → 记入"独立里程碑"或直接拒绝。

## 六、给 AI 的执行约定（每期都带上这段）

- 本期只做指定阶段章节范围内的事，**范围外一律记入后续阶段，不提前实现、不顺手实现**。
- 本文档只讲"迭代什么 / 为什么"，**不含实现**。凡涉及技术选型、数据结构、阈值、依赖，
  你必须先向用户澄清并达成一致，再动手；不得擅自折中或引入未经同意的新依赖。
- 每完成一个切片就停下等确认，再做下一个切片。
- 用户正在学习 Agent 开发：解释要讲"为什么"，帮他建立判断力，而不只是给结论。
