# 自由探索模式（explore-mode）

用户选择了自由探索时的逐篇确认流程。核心：**每篇笔记的「是否深入」都是用户的决策，不是你猜的。**

## 启动

1. 先跑 1 轮 `scripts/collect-page.js` 拿到初始卡片池（`maxScrolls: 1`），形成待处理队列。
2. 队列不空时逐篇处理；队列空了再跑一轮 collect-page 补充。

## 逐篇确认循环

对队列中的每篇笔记：

1. 用 ask_user 询问（question 里带上笔记标题和点赞数，最多 120 字）：
   - 「深入读取详情+评论」
   - 「只看详情」
   - 「跳过这篇」
   - 「停止探索」（放入 options 最多 4 项）
2. 按答案执行：
   - 深入 → open-note → read-note → read-comments → close-note；open-note 没打开时不要连续点击，改问用户怎么处理。
   - 只看详情 → open-note → read-note → close-note；open-note 没打开时不要连续点击，改问用户怎么处理。
   - 跳过 → 记录跳过原因留空，继续下一篇
   - 停止 → 收尾：总结已读篇目，报告未读队列

## 补充队列

- 每处理 5 篇询问一次是否继续探索更多（二选一：继续 / 收尾总结）。
- 连续 2 轮 collect-page 无新增且 `atBottom` 未到 → 询问是否继续（可能触发了反爬限流）。

## 记录

- 每篇处理完都要在对话中留一行摘要（标题/互动数/评论数），便于最后汇总。
- selectorMiss、captcha 处理与指定数量模式一致。
